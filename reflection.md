# Reflection: building the AC & Side-Channel Lab with an AI-assisted workflow

I built this lab with Claude in the Claude desktop app. My job was less about typing code and more about specifying behavior precisely, then testing the result in the browser and sending corrections. I started with one long prompt describing all three modules: a timing-oracle password checker with an animated auto-crack, a ReDoS demo with a hand-written backtracking matcher that counts its own steps, and a simulation of the linked-list game where a static `next` field in Rectangle makes traversal loop. I also asked for a single offline HTML file with dark mode and keyboard access.

The first build mostly worked, but testing changed three things. The ReDoS sweep froze the tab near the top of the slider because the matcher had no limit on recursive calls; I asked for a five-million step cap that throws out of the recursion and plots the run as a hollow point on a cap line, which also makes the chart visibly saturate. The pointer diagram was hard to read when one arrow jumped backward over four nodes, so I asked for color-coded arrows (instance pointer, shared static pointer, cycle-closing pointer) and for the labels to move above the nodes so the loop could pass underneath. Finally, the auto-crack stalled whenever the placeholder character was already correct, since no candidate made the sleep drop; the fix was to notice when the sleep goes up by one instead.

Each module sharpened something I thought I already understood. For the timing channel I had to decide exactly what the attacker observes, and that made the Hamming-distance oracle concrete: the sleep is not "slow versus fast" but a count of wrong characters, which is why positions can be solved independently in about 24 plus 11 times 62 queries instead of 62 to the eleventh. Writing the constant-time version (XOR every byte into one accumulator, never branch or return early on secret data, no sleep) showed me the fix is about equalizing observable behavior, not hiding the comparison.

For ReDoS, implementing backtracking by hand made the explosion obvious in a way reading never did. The email pattern's tail class and the next group's head class overlap, so every boundary between blocks has several legal split points, and the `*` around the group multiplies them into k to the n minus 1 parses. On a benign input the first greedy parse succeeds; one trailing character forces the engine to visit all of them.

For the AC bug, modeling the static field as one shared object made it clear the problem is shared mutable state, not linked lists. A single Rectangle gets the one correct write; a Rectangle in the last slot plus any earlier one reads a pointer that points backward, and an O(n) walk becomes infinite.
